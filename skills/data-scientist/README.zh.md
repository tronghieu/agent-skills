# Data Scientist

**语言：** [中文](./README.zh.md) | [English](./README.md) | [Tiếng Việt](./README.vi.md)

将真实业务决策及其数据转化为经得起追问的证据、包含不确定性的结论和可供决策的报告。

## 安装

```bash
npx skills add tronghieu/agent-skills --skill data-scientist
```

## 立即尝试

```text
/data-scientist 探索 orders.csv：其中有什么、数据是否可信，以及应该检验哪些假设？
```

```text
/data-scientist 变体 B 的转化提升是真的吗？请给出效应量、置信区间和样本量含义。
```

```text
/data-scientist 用 sales.parquet 建立每周需求预测基线；缺货的成本高于库存过多。
```

```text
/data-scientist 在给管理层看之前红队审查这份流失 notebook：复算关键数字并找出泄漏或混杂因素。
```

## 为什么不使用普通聊天机器人？

普通聊天机器人可能直接给出图表、p 值或复杂模型。此 Skill 先确定要支持的决策、数据粒度、覆盖范围以及决策时可获得的信息。它要求由代码计算的证据、每个估计值的不确定性、复杂模型之前的简单基线，以及一轮尝试推翻结论的审查。结果不只是看似合理的分析，而是让决策所有者看清局限与权衡的分析。

## 适合谁，以及何时使用

当您拥有 CSV、Parquet、Excel、查询结果、API 导出、notebook 或已有模型，并且需要以下工作时使用：

- 在信任陌生数据集前先探索和审计它。
- 诊断指标变化，同时区分相关与因果。
- 设计或解读 A/B 测试、比较、置信区间或样本量。
- 建立并判断分类、回归、评分、分群或预测的基线。
- 在分析、notebook 或模型影响决策前审查它。
- 将技术发现转化为面向利益相关者的简洁报告。

它适合分析师、数据科学家、产品/业务团队和决策所有者，他们需要可被追问的证据，而非漂亮的叙述。

## 工作方式

Skill 首先将工作界定为描述性（发生了什么）、诊断性（为什么）、预测性（接下来可能发生什么）或建议性（选择哪种权衡）。它会确认所涉决策、分析单位、目标定义、可用信息的时间点、成功标准和各类错误的成本。如果所要求的模型无法改变任何行动，它可以将工作转向更有用的问题。

随后按严格路径推进：

1. **审计数据。** 确认来源、每行粒度、覆盖范围、键、定义、缺失、异常值、目标完整性，以及数据是否适合该目的。
2. **带着问题探索。** 考察分布、细分、时间结构和可能解释；最终给出可证伪、已排序的假设，而不是一堆图表。
3. **分析或预测。** 对诊断问题采用恰当的检验和效应量；或在模拟真实部署的数据切分下，将预测模型与简单基线比较。
4. **相信之前先验证。** 附上置信区间或交叉验证离散度；检查假设、多重比较、实际重要性、校准、重要细分的表现和数据泄漏。
5. **分享之前红队审查。** 有意从分析师切换为对抗性审阅者：复查关键计算、选择效应、混杂因素、因果措辞、替代切分或定义，以及哪些条件会推翻结论。
6. **传达决策。** 先用业务单位给出答案、不确定性、证据、量化后的选项和具体局限。Skill 提出建议；决策所有者作出选择。

## 证据与不确定性纪律

每一个报告的数字都必须能追溯到已经执行的分析。估计值附带置信区间、误差范围或验证离散度。观察性模式表述为**相关**；只有随机实验或经过明确论证的因果设计才使用因果措辞。看似异常准确的模型在检查特征时间点和验证泄漏之前会被视为可疑。

对于预测，复杂模型只有在比哑基线和线性基线高出正常验证波动时才值得保留。阈值会呈现为业务选择——获得什么、付出什么、谁受影响——而不会默认设为 0.5 或替您选择。

## 提供什么，以及如何协作

请分享数据或数据位置、问题或决策、目标人群和时间段、已知定义/约束，以及数据字典（如有）。对于预测工作，请说明何时作出预测、当时哪些输入合法可用、预测如何使用，以及哪类错误更昂贵。

若这些选择尚不明确，分析前会有简短的澄清问题。您也可以提供已有 notebook 或结果：审查路线会独立检查支撑结论的关键数字，并将问题分为致命、重大或轻微，同时给出具体修复方案。

## 您将获得什么

根据路线不同，工作会产生一组简洁、可复现的产物：

| 产物 | 用途 |
| --- | --- |
| 项目简报 | 决策、目标、粒度、成功标准和明确假设 |
| 数据画像与 EDA 报告 | 数据质量结论、主要发现、已排序假设和泄漏观察清单 |
| 统计解读 | 效应量、不确定性、假设和实际含义 |
| 实验日志与模型卡 | 可比较的运行、验证设计、基线对比、运行权衡和局限 |
| 洞察或批判报告 | 先给答案；再给证据、建议选项和可能改变结论的因素 |

## 有用的互补 Skill

- [Critical Thinking](../critical-thinking/README.zh.md) — 面对高风险建议时搭配使用，以更广泛地挑战论证、假设和决策逻辑。
- [Market Researcher](../market-researcher/README.zh.md) — 当问题还需要带引文的市场、竞争对手或行业证据时使用；此 Skill 随后分析您拥有的数据。
- [Diataxis Writer](../diataxis-writer/README.zh.md) — 分析后如需为不同读者制作可长期使用的教程、操作指南、参考或解释文档时使用。

## 限制

此 Skill 不替代数据工程、生产 MLOps、领域验证、隐私/安全工作或法律与伦理审查。它不会替您作出业务决定，也不构建完整的定价或资源分配优化器。薄弱、不完整、有偏或不具代表性的数据可能导向“**不适合该目的**”的结论；这是一项有效结果，而不是夸大确定性的理由。
