# Critical Thinking

**语言：** [中文](./README.zh.md) | [English](./README.md) | [Tiếng Việt](./README.vi.md)

审查备忘录、提案、分析、文章或草稿中的推理；同时训练你自己的判断力，而不是把判断交给 AI。

```bash
npx skills add tronghieu/agent-skills --skill critical-thinking
```

## 快速开始

尽可能发送完整文本或论点，并说明它要支持的决策。可以从以下任一提示词开始：

```text
/critical-thinking 快速审查这份供应商提案。我们今天必须决定是否将其列入候选名单；请只展示最可能改变该决定的三个问题。
```

```text
/critical-thinking 深度审查这份投资备忘录。梳理关键承重主张，检查其 warrant 和来源可信度，并告诉我什么证据会证伪该建议。
```

```text
/critical-thinking 审查我的董事会草稿。保留已经成立的部分，为每个重要漏洞给出具体修复方案，并在它交给持怀疑态度的读者前强化最强反对意见。
```

```text
/critical-thinking 我已完成八次审查。请做一次进展审查：反复遗漏的类型、信心校准、跳过 commit 的比例，以及下一步最该注意的一件事。
```

## 为什么不只是问聊天机器人？

通用聊天机器人可以给出一段看似合理的批评。这个技能让批评可复核，也让它有助于学习：

- 每项发现都锚定原文的准确引文和位置，因此你能核查审查，而非相信它的语气。
- 它区分推理断裂、未经核实的事实、未说明的假设，以及诚实的意见分歧。
- 它只审查支撑结论的关键主张，再按对决策的影响排列问题。
- 默认先询问你的判断，因此审查成为对照和一次练习，而不是替代你的判断。

你仍然对决策负责。这个技能提供的是对呈交给你的推理进行结构化、对抗性检查。

## 适合谁

当你需要判断一份文档真正证明了什么、只是假设了什么，以及行动前还应验证什么时，请使用此技能。它适合处理投资备忘录、供应商提案、董事会材料、战略说明、评论文章或自己草稿的决策者、分析师、顾问、审阅者、创始人和写作者。

## 心智模型：文风不是论证

审查会重建文档之下的推理，而不是复述各个章节。

1. **说明决策请求。** 它区分被请求的决策（例如“批准预算”）与用于证明该决策的信念主张（例如“该市场将增长 30%”）。
2. **找出关键承重主张。** 它识别约 3–7 个一旦失败就会令结论坍塌的主张，并将每项锚定到原文。
3. **揭示推理桥梁。** 每项主张都以 Toulmin 图谱记录 grounds（证据）、warrant（证据为何支持主张）、qualifier（表述有多确定）和 rebuttal（如何处理反例）。经常被隐藏的 warrant 正是许多措辞漂亮的论证断裂之处。
4. **尝试证伪。** 审查揭示隐含假设，检查来源可信度和替代解释；它会先绘制论证图，再只扫描有原文锚点的谬误或偏差，并追问什么可观察证据会证明结论错误。

每项发现只使用一个诚实标签：

| 标签 | 含义 |
| --- | --- |
| `[GAP]` / `[LEAP]` | 缺少证据 / 有证据但无法推出该结论 |
| `[ASSUME]` / `[CONFLICT]` | 关键的隐含前提 / 两个陈述无法同时成立 |
| `[FALLACY]` | 有名称且锚定原文的推理模式，而非审查者不喜欢的主张 |
| `[OPINION]` / `[CANNOT-ASSESS]` | 诚实的意见分歧 / 需要外部专业知识或数据的主张 |

深度审查还会检查清晰度、准确性、精确性、相关性、深度、广度、逻辑、重要性、公正性和来源可信度。这些维度不会被平均成一个让人安心的分数：文字清楚但结论无法由证据推出，仍是薄弱论证。

## 一次审查如何进行

1. **发送文档和利害关系。** 说明它要支持的决策，以及缺失附件、截止时间或最重要的风险。
2. **选择深度。** 快速审查用于分流，深度审查用于重要决策，草稿审查用于强化自己的写作。
3. **先作出承诺（通常如此）。** 在看到审查前，先说出你的看法：论证是否成立？信心有多高？最弱点是什么？深度审查还会问一个隐含假设。时间紧急时可以说 `skip`。
4. **接收审查。** 报告先给出可执行的结论，随后提供论证图和按严重程度排序、附精确引文的发现。它会说明未审查的部分，而不会假装面面俱到。
5. **对照并学习。** 若先作出判断，报告会列出你发现了什么、遗漏了什么或担心了哪些未经证实的问题，并将信心与结果对照。反复使用时，可选的推理档案会记录有证据支撑的模式和校准情况，而不评价人格。

## 选择模式

| 模式 | 适用场景 | 你会得到 |
| --- | --- | --- |
| **Quick audit** | 短文档、低风险或时间有限 | 结论、推理骨架，以及最可能改变决策的三项问题 |
| **Deep audit** | 决策或文档具有关键承重性 | 完整论证图、假设、来源与谬误检查、证伪测试，以及发给作者的问题 |
| **Draft review** | 文档由你撰写 | 已经成立的部分、关键漏洞的修复方案、最强反对意见，以及缺失的阶段门或 go/no-go 标准 |
| **Progress review** | 你已经多次使用该技能 | 审查构成、反复遗漏的类型、信心校准，以及一个明确的下一步练习重点 |

## 你会收到什么

报告先给出结论，随后是论证图和按严重程度（而非文档顺序）编号的发现。深度审查还可能给出假设清单、可证伪性评估、将 `[OPINION]` 与 `[CANNOT-ASSESS]` 明确分开的“诚实区”，以及发回给作者的问题。草稿审查会增加修复路径和决策结构；进展审查只描述记录足以支持的模式。

## 有用的搭配技能

- 当审查将市场规模、竞争对手事实或其他外部主张标为 `[CANNOT-ASSESS]` 时，使用 [Market Researcher](../market-researcher/README.zh.md)：先确认事实，再重新审查依赖这些事实的推理。
- 当文档审查发现背后其实是公司级战略选择，需要多位高管视角和完整建议时，使用 [Strategy Board](../strategy-board/README.zh.md)。
- 当提案声称“用户想要 X”时，使用 [Design Thinking](../design-thinking/README.zh.md)：本技能检验已有论证，Design Thinking 则研究用户真正需要什么。
- 当目标变为通过引导式对话学习一个主题，而不再是检验某一具体论证时，使用 [Socratic Questor](../socratic-questor/README.zh.md)。

## 限制

这是一项对文档中现有推理的审查，不保证每项专业事实都正确。缺少的数据或专业知识会被标为待验证，而不是猜测。引文锚点让工作可检查，并不让它绝对无误；重大的法律、医疗、财务、技术或监管决策仍需要相应领域专家复核。
