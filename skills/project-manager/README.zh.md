# Project Manager

**语言：** [中文](./README.zh.md) | [English](./README.md) | [Tiếng Việt](./README.vi.md)

把充满不确定性的交付工作变成有证据的计划、诚实的预测和清晰的决策记录。

## 快速安装

```bash
npx skills add tronghieu/agent-skills --skill project-manager
```

## 从真实项目需求开始

用自然语言调用 `/project-manager`。例如：

```text
/project-manager 把这份粗略范围变成里程碑计划，列出依赖、负责人和可信的交付日期区间。
/project-manager 我们错过了集成里程碑。请建立风险登记表，做一次预演失败，并建议下一项决策。
/project-manager 起草本周指导委员会状态报告：把坏消息放在开头，标明证据，并列出需要的决策。
/project-manager 评估新增 SSO 的请求：在接受前说明它对范围、进度、成本、风险和质量的影响。
```

## 为什么不用普通聊天机器人？

普通聊天可以在信息不足时生成漂亮计划或令人安心的绿色报告。Project Manager 的设计目标是让每一项交付主张都可审计：

- 日期、估算、进度和 RAG 状态都关联证据、带日期的用户陈述或明确假设。
- 估算使用区间，并与项目历史或说明的参考类别核对；缓冲单独可见。
- 范围、日期或预算变更在修改基线前，必须先完成影响评估，并由明确的决策授权人处理。
- 计划、状态报告和变更决策都会接受对抗式审查，使风险和薄弱证据在行动前暴露出来。

## 适合谁

如果你是对承诺交付负责的项目经理、项目集经理、PMO、交付负责人、团队负责人或发起人，请使用它：范围、进度、预算、风险、利益相关者或状态报告均在职责内。这是面向持续项目的副驾驶，不是入门课程或通用任务清单生成器。你仍保留决策权和对外承诺权。

## 可以用它做什么

- 以项目章程、成功标准、决策授权和适合的交付方法启动项目。
- 建立 WBS 或 backlog、依赖、里程碑进度表、关键路径和基线。
- 制定区间估算、风险登记表、ROAM 应对、预演失败和恢复方案。
- 产出坦诚的周报、指导委员会材料、利益相关者沟通、会议行动和决策记录。
- 控制变更、透明地重新设定基线、记录经验，并汇总多个项目而不以平均值掩盖红色项目。

## 交付方法与执行纪律

这是一本 playbook，而非强制流水线：从当前问题进入，再按需要衔接其他工作。典型交付循环为：

1. **定向：**确认目标、范围内/外事项、成功标准、利益相关者、汇报节奏和授权人。
2. **计划与估算：**拆分工作和依赖，选择预测区间，明确假设和缓冲，准备好后冻结基线。
3. **降险与交付：**审查风险、行动、证据和实际进展；如实报告预测。
4. **决策与学习：**先评估变更再批准，保留旧基线，并把计划与实际的经验带入下一次估算。

它按项目调整产物形态，而不是反过来：预测型项目使用 WBS、关键路径和阶段门；敏捷项目使用考虑产能的 backlog、发布或 sprint、burnup 和流动指标；混合项目结合里程碑主线与迭代交付。无论方法如何，纪律相同：不编造事实，先传递坏消息，记录带复查触发条件的决策，并让不确定性保持可见。

三道审查门保护关键产物。基线前，计划检查负责人、验收证据、依赖、缓冲、预演失败结果、范围一致性和风险处理。状态报告发送前，检查信息来源、诚实的进度、恢复行动、预测可信度，以及高管和团队视角是否一致。变更执行前，检查进度、成本、风险和质量影响；授权；基线处理；以及相关文件是否同步更新。

## 如何协作

对于持续工作，技能维护一个 `_project/` 工作区，包含项目背景、计划、带日期的状态快照，以及证据、假设、风险、行动、变更、决策和经验的动态登记表。你回来时，它会基于当前状态和近期决策继续，而不是假装记得过去。

它只询问当前 play 所缺的输入，指出与记录相冲突的地方，并能在事实不足时提供明确标注假设的草案。它不会捏造队友意见，也不会悄悄接受变更。PM 会在章程、结构、估算、风险、讲真话、变更、利益相关者、学习和审计等 lens 间切换。**Solon** 是审计 lens：计划、状态报告或变更决策发出前，它会进行独立的对抗式复核；如有独立 agent，该复核可以单独执行。

## 你需要提供什么，会获得什么

请提供已有材料：目标、当前范围、约束、目标日期、团队产能、利益相关者、已知依赖、当前进展、来源材料、过往估算或实际数据，以及有决策权的人。缺失信息会记录为假设或问题，而不是伪装成事实。

你可以得到项目章程；进度表或 backlog；估算区间；风险、证据、决策、变更或行动登记表；状态报告或指导委员会材料；利益相关者沟通；会议结果；恢复建议；或项目组合汇总。回复先给出交付结论、关键数字的证据，以及需要作出的决策或行动。

## 配套技能

- 在承诺交付前，需要决定**做什么、为谁做或如何排序**？使用 [Product Manager](../product-manager/README.zh.md) 做优先级、PRD 和产品证据；把已批准范围带入项目计划。
- 需要高管层作出**投资、项目组合优先级、终止/继续或重大重新定范围**的决定？使用 [Strategy Board](../strategy-board/README.zh.md)。Project Manager 提供交付事实；board 评估战略选择。
- 需要检验**供应商承诺、项目挽救方案或高风险决定**背后的推理？使用 [Critical Thinking](../critical-thinking/README.zh.md) 审查论证，再把有依据的发现登记为项目证据。

## 限制

如果你不提供材料，该技能无法知道实际进展、产能、供应商承诺、内部政治或历史表现。它支持并质疑决策；不会替你批准范围、作出承诺、取代专业/法律/财务/人员判断，或保证结果。详细 play、schema 和证据约定见 [`references/`](./references/)。
