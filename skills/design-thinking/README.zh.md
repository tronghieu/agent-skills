# 设计思维（Design Thinking）

**语言：** [中文](./README.zh.md) | [English](./README.md) | [Tiếng Việt](./README.vi.md)

把真实用户证据转化为聚焦的问题、概念组合和可证伪的测试，同时不编造人物画像、引语或研究结论。

```bash
npx skills add tronghieu/agent-skills --skill design-thinking
```

## 快速示例

```text
/design-thinking 用户在使用学习应用一周后流失。请帮我定义问题，并为成人学习者设计一套非诱导式访谈计划。

/design-thinking 我有八份关于小商户接受数字支付的访谈逐字稿。请综合为有证据支持的洞察，仅在细分真实存在时创建人物画像，然后提出 HMW 问题。

/design-thinking 我们已有可点击的结账原型。请绘制最高风险假设，并设计一个预先固定通过/失败标准的可用性测试。
```

## 为什么不只和普通聊天机器人对话？

普通对话可以快速生成看似合理的创意，也可能生成同样“合理”但虚构的用户洞察。本技能增加了方法纪律：

- 每个证据来源都有 `[S#]`；每条洞察 `[I#]` 都必须追溯到来源。
- 缺乏支持的判断会始终标为假设；人物画像不会为了生动而添加虚构细节。
- 持久的项目记录会跨会话保存决策、开放问题和循环返回。
- 明确的关卡避免流程在证据或你的决定尚未就绪时继续推进。
- 独立创意视角减少锚定；对抗式审核挑战看似精彩但薄弱的结论。
- 测试针对风险最高的假设，并在看到结果前固定标准。

## 这个技能是什么，适合谁？

Design Thinking（设计思维）是一种以人为中心的迭代方法，帮助团队在投入解决方案前先了解人们的真实需求。本技能可以引导完整的 **Empathize → Define → Ideate → Prototype → Test** 循环，也可以只支持其中一个阶段，例如编写访谈指南或测试已有原型。

它适合产品经理、UX 研究员、设计师、服务团队、创始人和创新团队。你需要能够接触真实用户，或拥有真实证据，例如访谈笔记、逐字稿、支持工单、问卷、分析数据或测试结果。

## 方法如何运行

| 阶段 | 发生什么 | 关卡或交接 |
| --- | --- | --- |
| **Kickoff** | 明确问题、目标用户、范围、约束和现有证据。 | 由你确认问题框架。 |
| **Empathize** | 设计研究问题、招募条件、访谈/观察指南，以及基于过去行为的非诱导问题。 | 技能暂停，由你开展研究并带回真实数据。 |
| **Define** | 提取观察，按张力做亲和图，形成有证据的洞察；只有当数据支持有意义的细分时才建立人物画像。再把结果转化为 POV 和 How Might We（HMW）问题。 | 洞察审核检查来源、引语、假设、替代解释和画像细节；你选择 3–5 个 HMW。 |
| **Ideate** | 先不评判地发散，再在独立环节收敛。第一性原理、类比领域、SCAMPER、极端用户、逆向思考和技术驱动等独立视角产生多样方案，再共同讨论需求性、可行性和商业可行性。 | 你选择 1–3 个概念并公开尚未验证的假设。 |
| **Prototype** | 构建能回答一个明确问题的最低保真产物：故事板、线框图、礼宾/Wizard-of-Oz 流程、fake door 或功能切片。说明哪些是真的、哪些是模拟的，以及要观察什么行为。 | 只有能支持可测量测试时，原型才算就绪。 |
| **Test** | 绘制假设地图，选择影响最高且最不确定的假设，再预先登记包含参与者、流程、指标和通过/失败阈值的测试卡。 | 你执行测试前先做假设审核；结果写入学习卡。 |

结果并不默认是“继续”。证据会导向四种明确决定之一：**persevere**（坚持方向）、**iterate**（迭代原型）、**pivot**（回到问题定义）或 **stop**。每次循环都会记录轮次和原因。

## 引导过程是什么体验？

技能通过主引导师 **Helm** 与你协作。Helm 保存项目状态、引导决策，并根据任务切换工作视角：

- **Lens** 设计用户研究；**Radar** 补充市场和可行性背景。
- **Loom** 把证据综合成洞察、人物画像、POV 和 HMW。
- **Prism** 通过多个独立视角开展创意发散。
- **Forge** 规定以学习为目的的原型；**Probe** 设计可证伪测试。
- **Judge** 在两个关键关卡独立审核洞察和假设。

这些是功能视角，不是需要你管理的角色。Helm 会说明当前模式、展示产物，并在需要你决定时暂停。在 Ideate 阶段，多个 Prism 视角可先独立贡献，再比较各自的方案；Judge 也可以独立审核，避免直接认可刚刚生成的推理。

流程会有刻意的暂停：技能负责设计研究和测试，但必须由**你或你的团队实际执行**。技能可以通过角色扮演帮助你排练访谈，但会明确标为模拟，并且绝不作为证据。你在后续会话返回时，技能会从记录的阶段继续，而不是重新开始。

## 你需要提供什么？

可以从现有材料直接开始：

- 问题或决策、目标用户、范围、约束和成功定义。
- 现有原始证据，以及足够准确登记来源的背景。
- 可以接受访谈或试用原型的真实参与者渠道。
- 若想直接从 Prototype 或 Test 开始，可提供已有概念或原型。

如果尚无一手研究，你可以明确选择“仅假设”模式。此时洞察仍标为假设，人物画像明确标为 **proto-persona**，而 Test 是现实第一次验证或否定这些判断的机会。

## 你将获得什么？

根据起点不同，交付物可包括：研究计划与访谈指南、来源登记表、有证据链的洞察和人物画像、POV 与 HMW、经过评估的创意组合、原型说明、假设地图、预登记测试卡、学习卡，以及支持跨会话工作的决策日志。

## 推荐搭配的技能

以下是推荐的辅助技能，并非前置条件：

- [`market-researcher`](../market-researcher/README.zh.md)：用于市场规模估算、竞争对手深度分析、趋势或更广泛的需求信号。其案头研究可提供有来源的背景，但不能替代一手用户研究。
- [`product-manager`](../product-manager/README.zh.md)：当用户需求和概念较清晰后，用于产品优先级、规格、路线图选择、指标或发布计划。

## 重要边界

案头研究不能证明*你的*用户怎么想或会不会购买。本技能不会编造访谈数据，也不会悄悄把假设升级为事实；它不能代替你招募参与者或开展现实研究。测试结果用于支持，而不是取代你的判断、伦理责任和领域专业知识。对于 fake door 或承诺测试，不要收取无法诚实履约或退款的费用。
