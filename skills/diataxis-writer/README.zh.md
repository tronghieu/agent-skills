# Diataxis Writer

**语言：** [中文](./README.zh.md) | [English](./README.md) | [Tiếng Việt](./README.vi.md)

Diataxis 是一种按读者当下需求组织文档的框架：通过实践**学习**、**完成**任务、**查找**事实，或**理解**概念。此技能利用这一划分，把混杂、难以导航的文档变成承诺明确的页面——更易使用，也更易维护。

## 快速安装

```bash
npx skills add tronghieu/agent-skills --skill diataxis-writer
```

## 快速示例

```text
/diataxis-writer 审查这份入门指南。找出混杂的章节，并提出教程、操作指南、参考文档和解释说明的结构。
```

```text
/diataxis-writer 将这份部署流程改写为面向任务的操作指南。保留前提条件、验证方法和恢复指引。
```

```text
/diataxis-writer 为这些 CLI 选项、默认值、限制和示例创建易于扫描的参考文档。
```

```text
/diataxis-writer 为新工程师解释这个身份验证设计，包括心智模型、权衡和后果。
```

## 为什么不只让聊天机器人“改进文档”？

这种宽泛的要求可能会改善措辞，却仍让页面目的不清，或把新手教学、任务步骤、查询事实和设计理由混在一起。此技能从读者任务开始，为每个页面设定一个主要承诺，并指出应保留、移动、拆分或链接的内容。产出的是文档结构，而不只是更流畅的文字。

## 适合谁

适合维护用户文档或内部文档的技术写作者、开发者关系人员、文档负责人、产品和工程团队、知识管理人员及运营人员。

## 适用场景

- 入门教程、帮助中心文章和内部流程文档
- 操作指南、runbook、配置、迁移和故障排除文档
- API、命令、政策和配置参考
- 概念解释、架构背景和设计理由
- 审查混乱页面或重组文档体系

## Diataxis 的四个象限

| 读者意图 | 文档类型 | 页面承诺 |
| --- | --- | --- |
| 通过实践学习 | 教程 | 沿着引导路径获得基础能力。 |
| 完成任务 | 操作指南 | 达成具体结果。 |
| 查找事实 | 参考文档 | 快速找到准确、完整的信息。 |
| 理解背景 | 解释说明 | 理解概念、决策和权衡。 |

## 如何分类和重构

1. 明确读者、其眼前目标，以及页面隐含的承诺。
2. 按四种读者意图对现有内容分类。
3. 为每个页面选择一种主要类型；辅助内容应放到相关页面或用简短链接指向它。
4. 保留、移动、拆分或改写混杂的章节，再连接最终页面，让读者可以在学习、执行、查找和理解之间切换。
5. 检查标题、开头、结构和详略是否实现了所承诺的读者任务。

详见 [Diataxis 模式与模板](./references/diataxis-patterns.md)。

## 你需要提供什么、将获得什么

提供文档或文档集、目标读者、产品或流程背景以及期望结果。已有示例、支持问题和搜索数据会有帮助。

你将获得分类结果、章节级的混杂目的发现、目标信息架构，以及具体的重写计划或已重写的内容。审查还会附带验证清单。

## 互补技能

- 当大型或内容密集的文档集需要仔细、可追溯地阅读时，请在此技能**之前**使用 [Deep Reader](../deep-reader/README.zh.md)；它提供重构所依赖的源材料理解。
- 当文档提出重要主张或建议时，使用 [Critical Thinking](../critical-thinking/README.zh.md)；它检验证据和推理，而 Diataxis 负责组织读者体验。
- 当产出的文档流程需要成为 LLM 产品中可重复的行为时，使用 [System Prompt Creator](../system-prompt-creator/README.zh.md)；它把期望的工作流和护栏转化为可测试的系统提示词。
- 在此技能**之后**使用 [Humanizer](https://github.com/blader/humanizer)，从完成的文字中去除 AI 写作痕迹。Diataxis Writer 在该技能已安装时会自动调用它，未安装时则退回使用更简短的内置检查清单。安装命令为 `npx skills add blader/humanizer`。

## 局限

Diataxis 适用于帮助人们学习、执行、查找或理解的文档。它不是营销文案、销售提案、法律合同、新闻稿、小说或其他以说服为首要目标内容的通用格式。一个页面可以借用多种信息，但仍应有一个主要读者任务。
